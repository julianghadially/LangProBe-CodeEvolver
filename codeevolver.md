## ARCHITECTURE TITLE: 5-Hop Retrieval with Retry Mechanism, Removed no_results_queries, Strengthened False-Presence and Step 4 Prompts

## ARCHITECTURE SUMMARY:
`HoverMultiHopPipeline` (`langProBe/hover/hover_pipeline.py`) is the top-level DSPy module evaluated per row. It wraps `HoverMultiHop` (`langProBe/hover/hover_program.py`), a fixed 5-hop retrieval chain, inside a `CountingRM` (`langProBe/hover/counting_rm.py`) instrumented retrieval model that tracks how many ColBERT searches are fired per example.

The inner `HoverMultiHop` module performs five sequential hops with k=7 per retrieval. Hop 1 retrieves on the raw claim. Hops 2–5 each call `ChainOfThought(IdentifyNextTarget)` via `_get_query_with_retry()`, a new static method that detects duplicate queries (using normalized comparison via `_normalize_query()`) and retries once with a `[CRITICAL]` warning injected into `previous_queries`. Key improvements over the prior iteration: (1) **Duplicate-query retry** — `_get_query_with_retry()` catches cases where the LM still outputs a repeated query and forces a second attempt; (2) **Removed `no_results_queries`** — this field was inert since ColBERT never returns zero results, and its removal simplifies the signature and prompt; (3) **Strengthened Step 2** — added a concrete false-presence example ("if you retrieve 'Person A | ...text mentioning Person B...', that does NOT cover Person B"); (4) **Strengthened Step 4** — added an immediate-action directive for implied entities and a new bridge-entity example.

The `IdentifyNextTarget` signature now has three input fields (`claim`, `retrieved_passages`, `previous_queries`) — `no_results_queries` has been removed. Final docs are assembled via round-robin interleaving across all 5 hop lists, then capped at 21 documents.

## ARCHITECTURE DESCRIPTION:
**What the program does**: Given a factual claim from the HoVer multi-hop fact-checking dataset, the pipeline retrieves the set of Wikipedia articles that support or refute the claim. The dataset (`hover_data.py:hoverBench`) loads `hover-nlp/hover` from HuggingFace, filters to examples requiring exactly 2–3 supporting documents, and wraps each as a `dspy.Example(claim=..., supporting_facts=..., label=...)` with `claim` as the input key.

**Key modules and responsibilities**:
- `hover_pipeline.py / HoverMultiHopPipeline`: Outer pipeline; instantiates the LM (`openai/gpt-5.4-nano`, reasoning_effort="low"), wraps `dspy.ColBERTv2` in `CountingRM`, resets the per-thread search counter before each forward pass, then reads the count back into `result.search_count` after the inner program finishes. Inherits `LangProBeDSPyMetaProgram`.
- `hover_program.py / HoverMultiHop`: Core 5-hop DSPy module with k=7 documents per retrieval. Hop 1 retrieves directly on the claim. Hops 2–5 each use `_get_query_with_retry(ChainOfThought(IdentifyNextTarget))` to identify the single most important uncovered entity with duplicate-query protection. Deduplication is incremental (per-hop): `get_new_unique()` updates `seen_titles` after each hop and tracks ALL queries in `all_previous_queries`. Final docs are assembled via round-robin interleaving across all 5 hop lists, then capped at 21 documents.
- `hover_program.py / HoverMultiHop._normalize_query()`: Static method that lowercases, strips, normalizes unicode (NFC), and converts em/en-dashes to hyphens for fuzzy duplicate detection.
- `hover_program.py / HoverMultiHop._get_query_with_retry()`: Static method that calls a predictor and checks if the returned query duplicates any previously-searched query (via normalized comparison). If so, retries once with a `[CRITICAL: '...' was already searched]` warning appended to `previous_queries`.
- `hover_program.py / IdentifyNextTarget`: DSPy Signature with three input fields (`claim`, `retrieved_passages`, `previous_queries`) — `no_results_queries` removed as ColBERT never returns zero results. Step 2 now includes a concrete false-presence example. Step 4 now includes an immediate-action directive for implied entities and a bridge-entity example. Step 5 forbids repeating any query from `previous_queries`.
- `counting_rm.py / CountingRM`: Thread-safe retrieval wrapper using `threading.local()` for per-thread counters (safe for `dspy.Evaluate` parallel mode). Also monkey-patches `dspy.dsp.colbertv2` to use a shared, connection-pooled `requests.Session` with configurable timeout (60 s default) and retry backoff, addressing DNS resolution failures under concurrent load.
- `tracing_setup.py`: On import, calls `DSPyInstrumentor().instrument()` (openinference) once, attaching OpenTelemetry spans to every DSPy Predict/Retrieve/LM call for CodeEvolver's IterationArchitect trace inspection.
- `hover_utils.py`: Metric logic. `discrete_retrieval_eval_with_resource_penalty_and_feedback` normalizes gold and found title sets, checks subset containment (binary success), applies `PENALTY_PER_SEARCH * max(0, search_count - 2)` soft penalty, and returns `ScoreWithFeedback(score, feedback)` where feedback details missing documents, counts, and penalty values.

**Data flow**: `claim` → `HoverMultiHopPipeline.forward` → reset counter → `HoverMultiHop.forward` (hop1: ColBERT on raw claim k=7, dedup; hop2: `_get_query_with_retry(IdentifyNextTarget, previous_queries)` → entity → ColBERT k=7, dedup+track-query; hop3–5: same with accumulated query list; round-robin interleave all 5 hop lists; cap at 21) → `dspy.Prediction(retrieved_docs=[≤21 passages])` → attach `search_count` → metric compares `retrieved_docs[:21]` titles against `supporting_facts[*].key` → `ScoreWithFeedback`.

**Metric being optimized**: A composite float in [0, 1] equal to `1.0 - penalty` if all gold documents are found (0.0 otherwise), where penalty = 0.002 × max(0, searches − 2). The hard output constraint is ≤ 21 returned documents; there is no hard cap on search count, only the soft penalty.
