## ARCHITECTURE TITLE: Multi-hop Claim Retrieval Pipeline (HoverMultiHopPipeline + HoverMultiHop DSPy module with CountingRM/ColBERTv2 retrieval)
## ARCHITECTURE SUMMARY:
The Hover benchmark is a multi-hop fact-checking retrieval task: given a claim, retrieve up to 21 Wikipedia documents sufficient to cover all supporting facts. The system is a thin LangProBe/DSPy pipeline wrapper (`hover_pipeline.HoverMultiHopPipeline`) around a core DSPy module (`hover_program.HoverMultiHop`) that performs three sequential retrieval-summarize-query hops against a remote ColBERTv2 server. Retrieval effort is metered by a thread-safe `CountingRM` wrapper (`counting_rm.CountingRM`) that patches ColBERTv2's HTTP transport for connection pooling, longer timeouts, and retries, while tracking per-thread query counts. The pipeline exposes the configured LM (DeepSeek-V4-Flash via GMI Cloud/LiteLLM), the counting retriever, and the DSPy program, and attaches `search_count` to the emitted `dspy.Prediction`.

The metric being optimized (`hover_utils.discrete_retrieval_eval_with_resource_penalty_and_feedback`) checks whether all gold supporting-fact titles appear among the normalized titles of the top-21 retrieved docs, then subtracts a soft penalty (0.002 per search beyond a 2-search free budget) and returns a `ScoreWithFeedback` carrying textual diagnostics for reflective optimizers.
## ARCHITECTURE DESCRIPTION:
Pipeline entry point is `langProBe/hover/hover_pipeline.py` (`HoverMultiHopPipeline.forward(claim)`), which sets up DSPy context with its LM and the `CountingRM`-wrapped ColBERTv2 retriever, delegates to the inner program, and records how many searches were issued. The actual reasoning lives in `langProBe/hover/hover_program.py` (`HoverMultiHop`): Hop 1 retrieves k=7 docs for the raw claim and summarizes them; Hop 2 generates a refined query from claim+summary_1, retrieves 7 more docs, and summarizes again; Hop 3 generates a final query from claim+summary_1+summary_2 and retrieves 7 more. Concatenated passages (up to 21) are returned as `retrieved_docs`. Retrieval is served by `dspy.ColBERTv2` against a remote Modal-hosted endpoint; `langProBe/hover/counting_rm.py` (`CountingRM`) replaces ColBERTv2's GET implementation with a pooled `requests.Session` (pool_maxsize=100), 240s timeout, and up to 2 retries with 60s backoff, and uses `threading.local()` counts so multi-threaded eval runs each get an independent tally. Data comes from `langProBe/hover/hover_data.py` (`hoverBench`), which loads the `hover-nlp/hover` HF dataset, filters to ≤3-hop examples, and produces dspy.Examples with `claim`/`supporting_facts`/`label`. `langProBe/hover/__init__.py` registers the `BenchmarkMeta`. The optimized metric in `langProBe/hover/hover_utils.py` normalizes gold vs. found document titles with `dspy.evaluate.normalize_text`, requires the gold set to be a subset of the top-21 retrieved titles, computes `composite = success - PENALTY_PER_SEARCH * max(0, search_count - 2)` (floored at 0), and returns GEPA's `ScoreWithFeedback(score, feedback)` where feedback enumerates required/missing/retrieved docs, search count, penalty, and composite score for downstream reflective optimization.
