## ARCHITECTURE TITLE: Asymmetric-k (hop1=6, hops2-4=5, hop5=12) + NONE Guard + Seen-Titles Guard + Sub-Article Coverage Fix + Disambiguation Suffix Guidance

## ARCHITECTURE SUMMARY:
`HoverMultiHopPipeline` (`langProBe/hover/hover_pipeline.py`) is the top-level DSPy module evaluated per row. It wraps `HoverMultiHop` (`langProBe/hover/hover_program.py`), a conditional 4+1 hop retrieval chain, inside a `CountingRM` (`langProBe/hover/counting_rm.py`) instrumented retrieval model that tracks how many ColBERT searches are fired per example.

The inner `HoverMultiHop` module performs four mandatory sequential hops plus a conditional 5th hop using **asymmetric-k**: hop1 uses k=6 (exactly matching its 6 guaranteed round-robin slots, zero seen_titles pollution), hops 2–4 use k=5 each (6+5+5+5=21 exactly, zero eviction), and hop5 uses k=12 (expanded to catch articles at ranks 8–12). Two new guards prevent wasted hops: (1) **NONE guard** in `_get_query_with_retry` — if the LM outputs a placeholder like "none", "n/a", or "" (matched against a class-level `NONE_PATTERNS` frozenset), the call retries with an explicit warning; (2) **seen-titles guard for hop5** — if the LM proposes an entity already in `seen_titles`, a second `identify_hop5_target` call is made with a warning, and the retry result is adopted only if it names a genuinely new unseen entity. Three prompt improvements in `IdentifyNextTarget`: a SELF-CHECK at the end of Step 1 to enforce verbatim claim entity listing; a sub-article false-coverage clause in Step 2 (e.g., "Robert E. Howard bibliography" does not cover "Robert E. Howard"); and disambiguation suffix guidance in Step 3 (e.g., "The Secret Agent (TV series)", "Moonrunners (film)").

## ARCHITECTURE DESCRIPTION:
**What the program does**: Given a factual claim from the HoVer multi-hop fact-checking dataset, the pipeline retrieves the set of Wikipedia articles that support or refute the claim. The dataset (`hover_data.py:hoverBench`) loads `hover-nlp/hover` from HuggingFace, filters to examples requiring exactly 2–3 supporting documents, and wraps each as a `dspy.Example(claim=..., supporting_facts=..., label=...)` with `claim` as the input key.

**Key modules and responsibilities**:
- `hover_pipeline.py / HoverMultiHopPipeline`: Outer pipeline; instantiates the LM (`openai/gpt-5.4-nano`, reasoning_effort="low"), wraps `dspy.ColBERTv2` in `CountingRM`, resets the per-thread search counter before each forward pass, then reads the count back into `result.search_count` after the inner program finishes. Inherits `LangProBeDSPyMetaProgram`.
- `hover_program.py / HoverMultiHop`: Core 4+1-hop DSPy module with asymmetric-k retrieval (hop1=6, hops2-4=5, hop5=12). Hop 1 retrieves directly on the claim using `retrieve_hop1` (k=6). Hops 2, 3, and 4 each use `ChainOfThought(IdentifyNextTarget)` → `retrieve_k` (k=5). Hop 5 uses `ChainOfThought(IdentifyNextTarget)` → `retrieve_hop5` (k=12) — retrieval only executes if the returned query's normalized form is not already in `all_normalized_queries`. Two new guards: **NONE guard** in `_get_query_with_retry` detects placeholder LM outputs (checked against `NONE_PATTERNS` frozenset) and retries with a warning; **seen-titles guard** for hop5 detects when the LM proposes an already-retrieved article and retries `identify_hop5_target` with a warning. When hop5 fires and produces new results, **priority interleaving** is used: `hop1_new[:6]` fills positions 1-6 unconditionally, then hops 2-5 interleave round-robin for positions 7-21. When hop5 produces no new docs, the standard 4-hop equal round-robin runs unchanged. Final docs are capped at 21 documents.
- `hover_program.py / IdentifyNextTarget`: DSPy Signature with four input fields (`claim`, `retrieved_passages`, `previous_queries`, `fruitless_queries`). The prompt has three iter18 improvements: (Step 1 SELF-CHECK) explicit instruction to confirm ALL verbatim claim entities are listed before proceeding, including comparison subjects and date/person anchors; (Step 2 sub-article clause) sub-pages like "X bibliography | ..." do NOT count as covering entity X — only an exact "X | ..." title counts; (Step 3 disambiguation suffix) instructs the LM to append Wikipedia type qualifiers like "(film)", "(TV series)", "(video game)", "(song)" when a work title might match multiple articles. Also retains: Step 4 body-text scan with PRIORITY rule; Step 5 no-repeat-queries rule.
- `counting_rm.py / CountingRM`: Thread-safe retrieval wrapper using `threading.local()` for per-thread counters (safe for `dspy.Evaluate` parallel mode). Also monkey-patches `dspy.dsp.colbertv2` to use a shared, connection-pooled `requests.Session` with configurable timeout (60 s default) and retry backoff, addressing DNS resolution failures under concurrent load.
- `tracing_setup.py`: On import, calls `DSPyInstrumentor().instrument()` (openinference) once, attaching OpenTelemetry spans to every DSPy Predict/Retrieve/LM call for CodeEvolver's IterationArchitect trace inspection.
- `hover_utils.py`: Metric logic. `discrete_retrieval_eval_with_resource_penalty_and_feedback` normalizes gold and found title sets, checks subset containment (binary success), applies `PENALTY_PER_SEARCH * max(0, search_count - 2)` soft penalty, and returns `ScoreWithFeedback(score, feedback)` where feedback details missing documents, counts, and penalty values.

**Data flow**: `claim` → `HoverMultiHopPipeline.forward` → reset counter → `HoverMultiHop.forward` (hop1: ColBERT on raw claim k=6, dedup; hop2: `IdentifyNextTarget`(previous_queries, fruitless_queries) → entity → ColBERT k=5, dedup+track-query+track-fruitless; hop3: same k=5; hop4: same k=5; hop5: `IdentifyNextTarget` + NONE-guard + seen-titles-guard → if query not in all_normalized_queries → ColBERT k=12 dedup, else skip; if hop5_new non-empty → priority interleave [hop1[:6] then 4-way round-robin hops2-5], else 4-way equal round-robin hops1-4; cap at 21) → `dspy.Prediction(retrieved_docs=[≤21 passages])` → attach `search_count` → metric compares `retrieved_docs[:21]` titles against `supporting_facts[*].key` → `ScoreWithFeedback`.

**Metric being optimized**: A composite float in [0, 1] equal to `1.0 - penalty` if all gold documents are found (0.0 otherwise), where penalty = 0.002 × max(0, searches − 2). The hard output constraint is ≤ 21 returned documents; there is no hard cap on search count, only the soft penalty.
