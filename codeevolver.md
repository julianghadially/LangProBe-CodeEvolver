## ARCHITECTURE TITLE: 4+1 Conditional Hop Retrieval with Priority Interleaving for Hop5 — Preserves Hop1's 6 Slots

## ARCHITECTURE SUMMARY:
`HoverMultiHopPipeline` (`langProBe/hover/hover_pipeline.py`) is the top-level DSPy module evaluated per row. It wraps `HoverMultiHop` (`langProBe/hover/hover_program.py`), a conditional 4+1 hop retrieval chain, inside a `CountingRM` (`langProBe/hover/counting_rm.py`) instrumented retrieval model that tracks how many ColBERT searches are fired per example.

The inner `HoverMultiHop` module performs four mandatory sequential hops plus a conditional 5th hop with k=7 per retrieval. Hop 1 retrieves directly on the claim. Hops 2–4 each call `ChainOfThought(IdentifyNextTarget)` to identify the next uncovered Wikipedia entity. Hop 5 also calls `ChainOfThought(IdentifyNextTarget)` but only executes retrieval if the LM identifies a genuinely new entity (one whose normalized query string was not already in `all_previous_queries`); otherwise the 5th search is skipped entirely and the 4-hop round-robin is preserved. Six key mechanisms: (1) **Incremental deduplication** — `seen_titles` is updated after each hop; (2) **All-queries tracking** — every hop's query is added to `all_previous_queries`; (3) **Fruitless-query detection** — zero-yield queries are added to `all_fruitless_queries` and passed to subsequent LM calls; (4) **Conditional 5th hop** — fires only when the LM identifies an entity not already queried, preventing slot displacement when no new target exists; (5) **Priority interleaving when hop5 fires** — hop1 claims positions 1-6 first, then hops 2-5 do a 4-way round-robin for positions 7-21, preserving hop1's 6-slot guarantee and eliminating the false-coverage bug; (6) **Equal round-robin when hop5 doesn't fire** — identical to the 4-hop baseline, zero regression.

## ARCHITECTURE DESCRIPTION:
**What the program does**: Given a factual claim from the HoVer multi-hop fact-checking dataset, the pipeline retrieves the set of Wikipedia articles that support or refute the claim. The dataset (`hover_data.py:hoverBench`) loads `hover-nlp/hover` from HuggingFace, filters to examples requiring exactly 2–3 supporting documents, and wraps each as a `dspy.Example(claim=..., supporting_facts=..., label=...)` with `claim` as the input key.

**Key modules and responsibilities**:
- `hover_pipeline.py / HoverMultiHopPipeline`: Outer pipeline; instantiates the LM (`openai/gpt-5.4-nano`, reasoning_effort="low"), wraps `dspy.ColBERTv2` in `CountingRM`, resets the per-thread search counter before each forward pass, then reads the count back into `result.search_count` after the inner program finishes. Inherits `LangProBeDSPyMetaProgram`.
- `hover_program.py / HoverMultiHop`: Core 4+1-hop DSPy module with k=7 documents per retrieval. Hop 1 retrieves directly on the claim. Hops 2, 3, and 4 each use `ChainOfThought(IdentifyNextTarget)` to identify the single most important uncovered entity. Hop 5 also calls `ChainOfThought(IdentifyNextTarget)` — but the retrieval only executes if the returned query's normalized form is not already in `all_normalized_queries` (the set of all prior hop queries). When hop5 fires and produces new results, **priority interleaving** is used: `hop1_new[:6]` fills positions 1-6 unconditionally, then hops 2-5 interleave round-robin for positions 7-21 (slot allocation: hop1→6, hop2→4, hop3→4, hop4→4, hop5→3). This eliminates the false-coverage bug from equal 5-hop round-robin where hop1's rank-6 doc was shown to the LM in context5 but displaced to position 26 and evicted from the final 21. When hop5 produces no new docs, the standard 4-hop equal round-robin runs unchanged. Context5 uses `hop1_new[:6] + hop2_new[:4] + hop3_new[:4] + hop4_new[:4]` (updated from [:5] for hops 2-3) to match the new secondary slot allocation. Deduplication is incremental (per-hop): `get_new_unique()` updates `seen_titles` after each hop, tracks ALL queries in `all_previous_queries`, and appends zero-yield queries to `all_fruitless_queries`. Both lists are passed to subsequent LM calls via `_get_query_with_retry`. Final docs are capped at 21 documents.
- `hover_program.py / IdentifyNextTarget`: DSPy Signature with four input fields (`claim`, `retrieved_passages`, `previous_queries`, `fruitless_queries`). The prompt instructs the LM to: (Step 1) enumerate ALL named entities including routes, botanical genera, and named scientific concepts; (Step 2) check coverage via article TITLE before " | ", treating `fruitless_queries` entries as covered; (Step 3) output the first uncovered non-fruitless Step 1 entity; (Step 4 — strengthened) scan body text for specific named songs/shows/musicals, botanical genera, doubles partners, stunt productions, or broader topic articles, with an explicit PRIORITY rule; (Step 5) never repeat a `previous_queries` entry.
- `counting_rm.py / CountingRM`: Thread-safe retrieval wrapper using `threading.local()` for per-thread counters (safe for `dspy.Evaluate` parallel mode). Also monkey-patches `dspy.dsp.colbertv2` to use a shared, connection-pooled `requests.Session` with configurable timeout (60 s default) and retry backoff, addressing DNS resolution failures under concurrent load.
- `tracing_setup.py`: On import, calls `DSPyInstrumentor().instrument()` (openinference) once, attaching OpenTelemetry spans to every DSPy Predict/Retrieve/LM call for CodeEvolver's IterationArchitect trace inspection.
- `hover_utils.py`: Metric logic. `discrete_retrieval_eval_with_resource_penalty_and_feedback` normalizes gold and found title sets, checks subset containment (binary success), applies `PENALTY_PER_SEARCH * max(0, search_count - 2)` soft penalty, and returns `ScoreWithFeedback(score, feedback)` where feedback details missing documents, counts, and penalty values.

**Data flow**: `claim` → `HoverMultiHopPipeline.forward` → reset counter → `HoverMultiHop.forward` (hop1: ColBERT on raw claim k=7, dedup; hop2: `IdentifyNextTarget`(previous_queries, fruitless_queries) → entity → ColBERT k=7, dedup+track-query+track-fruitless; hop3: same with accumulated lists; hop4: same; hop5: `IdentifyNextTarget` → if query not in all_normalized_queries → ColBERT k=7 dedup, else skip; if hop5_new non-empty → priority interleave [hop1[:6] then 4-way round-robin hops2-5], else 4-way equal round-robin hops1-4; cap at 21) → `dspy.Prediction(retrieved_docs=[≤21 passages])` → attach `search_count` → metric compares `retrieved_docs[:21]` titles against `supporting_facts[*].key` → `ScoreWithFeedback`.

**Metric being optimized**: A composite float in [0, 1] equal to `1.0 - penalty` if all gold documents are found (0.0 otherwise), where penalty = 0.002 × max(0, searches − 2). The hard output constraint is ≤ 21 returned documents; there is no hard cap on search count, only the soft penalty.
