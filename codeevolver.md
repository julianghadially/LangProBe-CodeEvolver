## ARCHITECTURE TITLE: SimplifiedBaleen multi-hop RAG with HTTP-injected retrieval, judged by LFRQA pairwise win-rate
## ARCHITECTURE SUMMARY:
The system is a multi-hop retrieval-augmented question-answering pipeline over the LoTTE "technology" corpus. `RAGQAArenaTechPipeline` (`RAGQAArenaTech_pipeline.py`) is a thin owner-wrapper that configures a DeepSeek-V4-Flash LM via GMI Cloud/LiteLLM and injects a process-wide singleton `HTTPEmbeddingRetriever` client into the pure-logic inner program, `SimplifiedBaleen` (`RAGQAArenaTech_program.py`). SimplifiedBaleen iteratively generates search queries with `dspy.ChainOfThought(GenerateSearchQuery)`, calls the injected retriever, deduplicates passages, and synthesizes a final `response` via `dspy.ChainOfThought("context, question -> response")`, carrying `pred.context` for downstream faithfulness scoring. Retrieval is decoupled from the optimizable program via a warm local server client (`RAGQAArenaTech_retrieval.py`). The metric under optimization is `ragqa_pairwise_winrate_feedback` (`metric.py`), a faithful double-polled bidirectional reproduction of RAG-QA Arena's LFRQA pairwise judge with directional feedback for CodeEvolver reflection.
## ARCHITECTURE DESCRIPTION:
`RAGQAArenaTechPipeline.__init__` builds a `dspy.LM` pointing at `openai/deepseek-ai/DeepSeek-V4-Flash` through GMI Cloud (`api_base=https://api.gmi-serving.com/v1`, `reasoning_effort="high"`), disables DSPy disk/memory caches for representative runs, obtains the process-wide retriever via `get_default_retriever()`, and constructs `SimplifiedBaleen(self.retriever)` as the default inner program (overridable so the optimizer can swap it). `forward(question)` scopes `dspy.context(lm=self.lm)` and delegates to `self.program(question=...)`. `SimplifiedBaleen` (`RAGQAArenaTech_program.py`) runs `max_hops=2` loops: each hop calls `generate_query[hop]` (a `ChainOfThought` over the `GenerateSearchQuery` signature in `RAGQAArenaTech_utils.py`) with accumulated context, searches the retriever for `num_docs=5` passages, deduplicates, then calls `self.respond = ChainOfThought("context, question -> response")` and attaches `pred.context` for grounding metrics. `HTTPEmbeddingRetriever` (`RAGQAArenaTech_retrieval.py`) is a thread-safe, connection-pooled client over a warm local server (`http://localhost:8894/api/search`) holding the 3.7GB embedding index; its `__deepcopy__` returns self so the optimizer never clones retrieval infrastructure. The optimized metric `ragqa_pairwise_winrate_feedback` (`metric.py`) reproduces the RAG-QA Arena LFRQA model-based pairwise protocol: it renders a verbatim system prompt + three ICL examples (vendored under `rqa_arena_eval/`), polls the judge (`gpt-5.4-mini`, temperature 0) twice with swapped answer order to cancel position bias, averages win=1.0/tie=0.5/loss=0.0, and returns a `ScoreWithFeedback` carrying question/gold/system text, the judge's `<reason>`, and directional guidance (improve factual grounding/coverage/faithfulness). `metric.py` also contains `ragqa_semantic_f1_feedback` (DSPy SemanticF1) and a composite `ragqa_cfc_feedback` (Completeness/Faithfulness/Conciseness) alternative metrics, all sharing the same lazy `JUDGE_LM` and CodeEvolver `(output, example, trace=...)` contract.
