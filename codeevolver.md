## ARCHITECTURE TITLE: 4+1 Conditional Hop Retrieval — Safe Asymmetric k (hops1-4=7, hop5=12) + None-query Guard + Step4 Director/Actress Pattern

## ARCHITECTURE SUMMARY:
`HoverMultiHopPipeline` (`langProBe/hover/hover_pipeline.py`) is the top-level DSPy module evaluated per row. It wraps `HoverMultiHop` (`langProBe/hover/hover_program.py`), a conditional 4+1 hop retrieval chain, inside a `CountingRM` (`langProBe/hover/counting_rm.py`) instrumented retrieval model that tracks how many ColBERT searches are fired per example.

The inner `HoverMultiHop` module performs four mandatory sequential hops plus a conditional 5th hop with safe asymmetric k: hops 1–4 use `retrieve` (k=7) to prevent `seen_titles` pollution (only 4 slots per hop in round-robin, so ranks 5-12 would land in `seen_titles` without entering the output, blocking later hops from using those documents), while hop 5 uses `retrieve_hop5` (k=12) — safe because it is the last hop with no subsequent hops to pollute, and beneficial when the target article is at rank 8-12 after ranks 1-7 are all already-seen duplicates. Seven key mechanisms: (1) **Safe asymmetric k retrieval** — k=7 for hops 1-4 prevents seen_titles pollution; k=12 for hop5 only is safe and expands coverage at the final stage; (2) **Incremental deduplication** via `seen_titles`; (3) **All-queries tracking** via `all_previous_queries`; (4) **Fruitless-query detection** via `all_fruitless_queries`; (5) **None-query guard** — `_get_query_with_retry` detects placeholder/invalid outputs (via `NONE_PATTERNS` frozenset) and issues a targeted retry with an explicit warning message; (6) **Conditional 5th hop** with priority interleaving when hop5 fires; (7) **Equal round-robin** when hop5 doesn't fire.

## ARCHITECTURE DESCRIPTION:
**What the program does**: Given a factual claim from the HoVer multi-hop fact-checking dataset, the pipeline retrieves the set of Wikipedia articles that support or refute the claim. The dataset (`hover_data.py:hoverBench`) loads `hover-nlp/hover` from HuggingFace, filters to examples requiring exactly 2–3 supporting documents, and wraps each as a `dspy.Example(claim=..., supporting_facts=..., label=...)` with `claim` as the input key.

**Key modules and responsibilities**:
- `hover_pipeline.py / HoverMultiHopPipeline`: Outer pipeline; instantiates the LM (`openai/gpt-5.4-nano`, reasoning_effort="low"), wraps `dspy.ColBERTv2` in `CountingRM`, resets the per-thread search counter before each forward pass, then reads the count back into `result.search_count` after the inner program finishes. Inherits `LangProBeDSPyMetaProgram`.
- `hover_program.py / HoverMultiHop`: Core 4+1-hop DSPy module with safe asymmetric k. Hops 1–4 use `retrieve` (k=7) directly; k=7 prevents seen_titles pollution because with only 4 round-robin slots per hop, ranks 5+ would be added to `seen_titles` without ever entering the output, silently blocking subsequent hops from using those documents. Hop 5 uses `retrieve_hop5` (k=12) — safe since it is the last hop (no subsequent hops to pollute) and beneficial when the target article is at rank 8-12 after ranks 1-7 are all already-seen duplicates. Hop 5 only executes retrieval if the returned query's normalized form is not already in `all_normalized_queries`. When hop5 fires and produces new results, **priority interleaving** is used: `hop1_new[:6]` fills positions 1-6 unconditionally, then hops 2-5 interleave round-robin for positions 7-21 (slot allocation: hop1→6, hop2→4, hop3→4, hop4→4, hop5→3). When hop5 produces no new docs, the standard 4-hop equal round-robin runs unchanged. The class-level `NONE_PATTERNS` frozenset and the `_get_query_with_retry` static method together guard against placeholder/invalid LM outputs ("none", "n/a", "null", etc.) by detecting them and retrying with an explicit critical warning injected into `previous_queries`. Deduplication is incremental (per-hop): `get_new_unique()` updates `seen_titles` after each hop, tracks ALL queries in `all_previous_queries`, and appends zero-yield queries to `all_fruitless_queries`. Final docs are capped at 21 documents.
- `hover_program.py / IdentifyNextTarget`: DSPy Signature with four input fields (`claim`, `retrieved_passages`, `previous_queries`, `fruitless_queries`). The prompt instructs the LM to: (Step 1) enumerate ALL named entities including routes, botanical genera, and named scientific concepts; (Step 2) check coverage via article TITLE before " | ", treating `fruitless_queries` entries as covered; (Step 3) output the first uncovered non-fruitless Step 1 entity; (Step 4 — extended) scan body text for specific named songs/shows/musicals, botanical genera, doubles partners, stunt productions, **directors/lead actors/choreographers/primary creators of already-retrieved film or musical works**, or broader topic articles, with an explicit PRIORITY rule; (Step 5) never repeat a `previous_queries` entry.
- `counting_rm.py / CountingRM`: Thread-safe retrieval wrapper using `threading.local()` for per-thread counters (safe for `dspy.Evaluate` parallel mode). Also monkey-patches `dspy.dsp.colbertv2` to use a shared, connection-pooled `requests.Session` with configurable timeout (60 s default) and retry backoff, addressing DNS resolution failures under concurrent load.
- `tracing_setup.py`: On import, calls `DSPyInstrumentor().instrument()` (openinference) once, attaching OpenTelemetry spans to every DSPy Predict/Retrieve/LM call for CodeEvolver's IterationArchitect trace inspection.
- `hover_utils.py`: Metric logic. `discrete_retrieval_eval_with_resource_penalty_and_feedback` normalizes gold and found title sets, checks subset containment (binary success), applies `PENALTY_PER_SEARCH * max(0, search_count - 2)` soft penalty, and returns `ScoreWithFeedback(score, feedback)` where feedback details missing documents, counts, and penalty values.

**Data flow**: `claim` → `HoverMultiHopPipeline.forward` → reset counter → `HoverMultiHop.forward` (hop1: ColBERT on raw claim k=7 via `retrieve`, dedup; hop2: `IdentifyNextTarget`(previous_queries, fruitless_queries) → entity [with None-guard retry] → ColBERT k=7 via `retrieve`, dedup+track-query+track-fruitless; hop3: same; hop4: same; hop5: `IdentifyNextTarget` [with None-guard retry] → if query not in all_normalized_queries → ColBERT k=12 via `retrieve_hop5` dedup, else skip; if hop5_new non-empty → priority interleave [hop1[:6] then 4-way round-robin hops2-5], else 4-way equal round-robin hops1-4; cap at 21) → `dspy.Prediction(retrieved_docs=[≤21 passages])` → attach `search_count` → metric compares `retrieved_docs[:21]` titles against `supporting_facts[*].key` → `ScoreWithFeedback`.

**Metric being optimized**: A composite float in [0, 1] equal to `1.0 - penalty` if all gold documents are found (0.0 otherwise), where penalty = 0.002 × max(0, searches − 2). The hard output constraint is ≤ 21 returned documents; there is no hard cap on search count, only the soft penalty.
