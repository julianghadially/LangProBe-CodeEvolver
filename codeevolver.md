## ARCHITECTURE TITLE: Asymmetric-k (hop1=6, hops2-4=5, hop5=12) + None-Query Guard + Seen-Titles Guard for Hop5

## ARCHITECTURE SUMMARY:
`HoverMultiHopPipeline` (`langProBe/hover/hover_pipeline.py`) is the top-level DSPy module evaluated per row. It wraps `HoverMultiHop` (`langProBe/hover/hover_program.py`), a conditional 4+1 hop retrieval chain, inside a `CountingRM` (`langProBe/hover/counting_rm.py`) instrumented retrieval model that tracks how many ColBERT searches are fired per example.

The inner `HoverMultiHop` module performs four mandatory sequential hops plus a conditional 5th hop with asymmetric k values: `retrieve_hop1` (k=6), `retrieve_k` (k=5 for hops 2–4), and `retrieve_hop5` (k=12). This eliminates "seen_titles pollution" — with k=6 for hop1 and 4-hop equal round-robin (6+5+5+5=21 slots), all retrieved docs enter the final output with zero eviction. Three additional quality guards: (1) **None-query guard** — `_get_query_with_retry` now detects placeholder LM outputs (e.g., "none", "n/a", "null") via `NONE_PATTERNS` and retries with an explicit warning; (2) **Seen-titles guard for hop5** — before firing hop5 retrieval, if the proposed query's normalized form is already in `seen_titles`, a retry is issued to obtain a genuinely uncovered entity; (3) **Expanded hop5 coverage** — k=12 for the last hop catches target articles at ranks 8–12 after earlier hops have deduplicated lower-ranked results.

## ARCHITECTURE DESCRIPTION:
**What the program does**: Given a factual claim from the HoVer multi-hop fact-checking dataset, the pipeline retrieves the set of Wikipedia articles that support or refute the claim. The dataset (`hover_data.py:hoverBench`) loads `hover-nlp/hover` from HuggingFace, filters to examples requiring exactly 2–3 supporting documents, and wraps each as a `dspy.Example(claim=..., supporting_facts=..., label=...)` with `claim` as the input key.

**Key modules and responsibilities**:
- `hover_pipeline.py / HoverMultiHopPipeline`: Outer pipeline; instantiates the LM (`openai/gpt-5.4-nano`, reasoning_effort="low"), wraps `dspy.ColBERTv2` in `CountingRM`, resets the per-thread search counter before each forward pass, then reads the count back into `result.search_count` after the inner program finishes. Inherits `LangProBeDSPyMetaProgram`.
- `hover_program.py / HoverMultiHop`: Core 4+1-hop DSPy module with asymmetric k values. `retrieve_hop1` (k=6): hop1 gets exactly 6 round-robin slots in both 4-hop equal round-robin and 5-hop priority interleaving — k=6 ensures zero seen_titles pollution. `retrieve_k` (k=5): hops 2–4 get 5 slots in 4-hop equal round-robin (6+5+5+5=21, zero eviction) and 4 slots in 5-hop priority interleaving — k=5 minimizes pollution vs the prior k=7. `retrieve_hop5` (k=12): hop5 is the last hop so it's safe to expand reach; k=12 catches target articles at ranks 8–12 after earlier hops exhaust lower-ranked duplicates. Hop 5 also includes a **seen-titles guard**: after `_get_query_with_retry` produces the hop5 query, if its normalized form is already in `seen_titles`, `identify_hop5_target` is called again with an explicit warning; the retry result is adopted only if it's genuinely new. The **None-query guard** in `_get_query_with_retry` uses the class-level `NONE_PATTERNS` frozenset to detect placeholder LM outputs ("none", "n/a", "null", "nil", etc.) and retries with a critical warning, separate from the duplicate-query retry path. Priority interleaving (hop1→6 slots, hops2-5 4-way round-robin for positions 7-21) is used when hop5 fires; equal 4-hop round-robin is preserved when hop5 produces no new docs.
- `hover_program.py / HoverMultiHop.NONE_PATTERNS`: Class-level frozenset of normalized placeholder strings the LM sometimes outputs instead of a Wikipedia article title. Checked by `_get_query_with_retry` before the duplicate-query check.
- `hover_program.py / IdentifyNextTarget`: DSPy Signature with four input fields (`claim`, `retrieved_passages`, `previous_queries`, `fruitless_queries`). The prompt instructs the LM to: (Step 1) enumerate ALL named entities including routes, botanical genera, and named scientific concepts; (Step 2) check coverage via article TITLE before " | ", treating `fruitless_queries` entries as covered; (Step 3) output the first uncovered non-fruitless Step 1 entity; (Step 4 — strengthened) scan body text for specific named songs/shows/musicals, botanical genera, doubles partners, stunt productions, or broader topic articles, with an explicit PRIORITY rule; (Step 5) never repeat a `previous_queries` entry.
- `counting_rm.py / CountingRM`: Thread-safe retrieval wrapper using `threading.local()` for per-thread counters (safe for `dspy.Evaluate` parallel mode). Also monkey-patches `dspy.dsp.colbertv2` to use a shared, connection-pooled `requests.Session` with configurable timeout (60 s default) and retry backoff, addressing DNS resolution failures under concurrent load.
- `tracing_setup.py`: On import, calls `DSPyInstrumentor().instrument()` (openinference) once, attaching OpenTelemetry spans to every DSPy Predict/Retrieve/LM call for CodeEvolver's IterationArchitect trace inspection.
- `hover_utils.py`: Metric logic. `discrete_retrieval_eval_with_resource_penalty_and_feedback` normalizes gold and found title sets, checks subset containment (binary success), applies `PENALTY_PER_SEARCH * max(0, search_count - 2)` soft penalty, and returns `ScoreWithFeedback(score, feedback)` where feedback details missing documents, counts, and penalty values.

**Data flow**: `claim` → `HoverMultiHopPipeline.forward` → reset counter → `HoverMultiHop.forward` (hop1: ColBERT on raw claim k=6, dedup; hop2: `IdentifyNextTarget`(previous_queries, fruitless_queries) → entity [None-guard retry if placeholder] → ColBERT k=5, dedup+track-query+track-fruitless; hop3: same; hop4: same; hop5: `IdentifyNextTarget` [None-guard retry] → seen-titles guard retry if already in seen_titles → if query not in all_normalized_queries → ColBERT k=12 dedup, else skip; if hop5_new non-empty → priority interleave [hop1[:6] then 4-way round-robin hops2-5], else 4-way equal round-robin hops1-4; cap at 21) → `dspy.Prediction(retrieved_docs=[≤21 passages])` → attach `search_count` → metric compares `retrieved_docs[:21]` titles against `supporting_facts[*].key` → `ScoreWithFeedback`.

**Metric being optimized**: A composite float in [0, 1] equal to `1.0 - penalty` if all gold documents are found (0.0 otherwise), where penalty = 0.002 × max(0, searches − 2). The hard output constraint is ≤ 21 returned documents; there is no hard cap on search count, only the soft penalty.
